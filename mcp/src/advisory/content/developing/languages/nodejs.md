# Developing Node.js applications

Node's single event loop is a good fit for one process per container. Keep it that way: one `node` process, no cluster module, no PM2 or other in-container supervisor. Kubernetes runs the replicas.

- Follow the failure-handling rules in `developing/general`: minimal `try` blocks, only expected errors handled locally, no blanket `catch` and no `unhandledRejection` or `uncaughtException` handler that swallows the error. Let an unexpected error crash the process; Node's default of exiting on an unhandled rejection is the right behaviour.
- Read configuration from `process.env` at startup into one typed object, validated once, and pass it down. Do not read `process.env` throughout the code, and do not load `.env` files in production; leave `dotenv` to local development.
- Treat `NODE_ENV` as a library switch, not an environment name. Its only sanctioned values are `production`, `development` and `test`. Frameworks read it to enable view caching and hide stack traces, and package managers skip `devDependencies` when it is `production`, so set it to `production` only in the runtime image, never before the build stage's `npm ci`. Do not branch application logic on it; use a separate variable such as `APP_ENV` when code must know which deployment it runs in.
- Size the heap from the container limit. V8 does not reliably read the cgroup memory limit, so a pod can be OOM-killed before a full GC runs. Set `--max-old-space-size` to about three quarters of the memory limit through `NODE_OPTIONS` in the deployment manifest, where the limit is known.
- Configure proxy trust behind the ingress. Express `trust proxy` and Fastify `trustProxy` must be enabled and scoped to the ingress's address range, or the client address, scheme and host seen by rate limiting, audit logs and redirects are the ingress's own.
- Listen on `::` so the server accepts IPv6 and IPv4. Node's `server.listen(port, '::')` does this on dual-stack hosts; do not bind to `0.0.0.0` or `localhost`.
- Handle `SIGTERM` explicitly. Call `server.close()` to stop accepting connections and let in-flight requests finish, close idle keep-alive connections, finish or return queued work, then exit. Without a handler Node exits at once and drops in-flight requests. Set `server.keepAliveTimeout` above the upstream proxy's idle timeout so the proxy does not reuse a connection the server is closing.
- Write logs as one JSON object per line to stdout with a structured logger such as `pino`. Do not use `console.log` for application logging and do not write log files. See `developing/logging`.
- Expose Prometheus metrics from a registry in the same process, following `developing/metrics`. `prom-client` with its default registry and default collectors is sufficient; do not use `cluster` aggregation.
- Keep the event loop free. Move CPU-heavy work to `worker_threads` or a separate service, and do not call the synchronous `fs`, `zlib` or `crypto` variants on the request path.
- Health-check endpoints must answer from process state only. See `developing/health-checks`.
- For local hot reload use `node --watch` or the framework's dev server through Compose, per `developing/local-development`. The production image runs the compiled entry file directly, as shown in `building/languages/nodejs`.
